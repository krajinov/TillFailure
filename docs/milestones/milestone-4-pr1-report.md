# Milestone 4 PR 1 report — online identity and clean-only departure

Status: **local emulator PR 1 acceptance passed on Android API 34 and a signed iOS 26.2 simulator, 2026-10-06.** This is not Milestone 4 completion or a production release approval.

## Implemented behavior

- Email/password Auth, online restoration, fresh account/workspace/membership proof, bounded server membership discovery, explicit denial/retry states and live revocation remain the PR 1 identity gate. A role shell is still pending.
- The product now initializes an encrypted, UID-partitioned local registry. Clean sign-out freezes account writes, requires a readable empty journal/upload/recovery partition, drains Firebase pending writes, durably records the departing UID and epoch, cancels account listeners/jobs, fences callbacks, signs out Auth, terminates and clears Firestore, removes the proven-empty local partition, disposes the account navigation state, clears the UID pin and completes the marker. A new Firebase app generation is named durably per active product installation; it rotates after successful cleanup so A's SDK generation cannot become B's.
- A failed registry proof, pending work, offline/stalled SDK drain, or marker-write failure keeps Auth unchanged and offers retry. Once the marker exists, failure or interruption enters `CleanupRequired`; startup resumes the marked UID's cleanup before observing Auth or allowing a different sign-in. Destructive discard and offline grants remain absent. Product Firestore uses a memory cache and still executes the SDK cleanup call; `clearPersistence` is not secure erasure.
- The shared gate exposes **Sign out** only for an observed signed-in UID on an adapter with the native departure port. The release hosts still have no emulator product client.

## Acceptance and limits

The **PR 1 emulator acceptance gate is met** for current product behavior: native clean sign-out is allowed only after the empty critical-work proof and SDK drain, and each post-marker interruption blocks B until cleanup succeeds. Existing sign-in, restoration, revocation, backend/Rules and release-isolation checks were rerun after the change.

This does not approve production Auth providers, shared-device retention or secure erasure. Physical iOS Keychain/Data Protection behavior remains untested. An installation from the earlier PR 1 draft that has a UID pin but lacks the initialized registry record fails the clean-sign-out proof; a reviewed migration or local test reset is needed for that installation. PR 1 has no product journal/upload writers yet; every later account-scoped writer must register its work in the protected registry and honor the freeze before this sign-out path can be used with that feature. Pending-work synchronization, destructive discard and offline workout access remain outside PR 1.

**Older UID-pin installations:** Do not synthesize an empty registry record or clear the pin in place: absence of the record is not proof that account-owned work is empty. For a disposable local Android emulator installation with no data to retain, clear the debug app's storage, reinstall the debug build, reseed only the named `demo-` Firebase emulators, and verify a fresh signed-out launch before testing A → B. For iOS, erase a dedicated test simulator before reinstalling; uninstalling the app alone may leave Keychain state. Never use this reset on a real user's installation. A production migration needs a separately reviewed, UID-bound inventory and preservation procedure that proves or reconciles every local critical-work source and SDK pending write before it creates the initialized registry; until then, keep sign-out and another-account entry blocked. A failed migration must retain the original pin and any recovery data.

Final review also covered an ambiguous marker-store acknowledgement: if the write reports failure but a marker is present or unreadable on recheck, the shared coordinator now enters `CleanupRequired` without unfreezing. Its focused shared test passed; the native acceptance results above retain their original attribution and were not rerun for this shared-only branch.
