### Fixed packet contract and independent metadata validation

Every packet is serialized with the complete `{"result": ...}` response wrapper, packet version 1, kind, exact identity binding, packet index/count and integral server time. The binding includes workspace/client/assignment identity, explicit schedule policy, assignment/horizon revision, source/copy/plan hashes and a canonical metadata hash. Historical policy-1 assignments retain their exact stored documents; only the packet envelope makes policy 1 explicit, with null plan digest and the existing implied revision 1. No stored metadata migration or access grant follows.

Packet 0 contains the complete safe header, inventory, snapshot metadata, all ordered workout metadata and all ordered plans. Independent validation needs **no item bytes, source DTO, network, prior response or authority cache**. It validates exact fields/types/schema/path identity, all hashes/provenance, old versus new schedule policy, source-order unique workout/item/plan identities, total item cap, exact sorted inventory, UTC time/expiry arithmetic, plan mapping/digest and every document ceiling. A valid empty description and multiline/escaped text remain supported. Metadata cannot independently prove the unseen item text hashes: the server has already validated the full graph, and the receiver withholds content until final complete reconstruction proves both hashes.

Item packets use stable source-workout/item order, exactly the next one or two complete item documents. Item count determines at most six packets, so total calls are `2 + ceil(totalItems/2)` (3–8). Requests select kind/index and the expected metadata digest, never arbitrary paths. Server paths come only from a bounded relative inventory, checked before references and then validated exactly. The last packet returns the entire final header plus its fresh server-time bound. Every request repeats current revoked-token-checked Auth, live enabled/verified caller **and target** Auth, all nine authoritative relationship documents, header/inventory and every copied child. It then validates the entire graph before returning any packet. Current trainer identity must match the header. Auth and Firestore remain separate services: a response authorized before an external Auth change may finish; no cross-service atomicity or instant recall is claimed. No source/version documents even exist in the live fixtures, and SDK interception observed **zero source reads**.

The receiving model is an isolated **memory-only request buffer**, with no persistent snapshot/cache or authority grant. It accepts only metadata → consecutive item pairs → final header. It rejects duplicates, gaps, reordering, mixed identities/digests, changed packet counts, missing/extra/partial documents and changed final headers, then validates the complete original graph/content hashes before releasing content. Any malformed packet or denied request clears and permanently invalidates that session. Background/account integration and UI are not wired by this prerequisite.

Each response uses a current transaction server-time value; regressed/invalid server clocks and expiry fail closed. The receiver subtracts the **full monotonic request latency rounded up**, requires nonregressing packet bounds and keeps the earliest conservative expiry deadline across the sequence. Fractional last-millisecond latency, expiry during a response, clock regression, nonfinite/coerced time and later access at the expiry boundary reject/clear. Neither a later packet nor device wall time can extend eligibility. A fresh sequence must reauthorize and reread everything.
