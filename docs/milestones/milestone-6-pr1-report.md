## Implemented contract

The trainer has a working Exercises Home action and bottom-navigation entry. Typed list/detail destinations carry only owner/visit and an exercise ID; no document body, page cursor or result is saved. Koin supplies a destination-scoped immutable MVI model. Detail opens with a fresh point read. Header/system Back returns to a new list visit/read. Current top destination, UID/workspace/role/authority epoch, visit, request generation and one-time effect consumption fence old callbacks/navigation. A client shell cannot open the trainer entry; this UI restriction does not alter global catalog Rules.

Both narrow official SDK adapters force fresh Auth token refresh, check native UID/generation/freeze/retirement and require the existing product **memory-cache** configuration. Android uses `Source.SERVER`; Swift uses `.server`. They issue only a fixed `systemExercises` query or validated exact ID get, never an arbitrary path/callable. The query is `status == published`, document ID ascending, `limit(21)`, optional `startAfter(lastDisplayedId)`: 20 visible rows and one lookahead. Every query/get re-evaluates existing Rules. A selected trainer workspace supplies shell eligibility; the fixed global entitlement independently supplies catalog access. Losing one contribution can leave catalog access through another; losing the final contribution denies it.

The complete strict stored-document allowlist is `schemaVersion`, `name`, `nameNormalized`, `muscleGroups`, `equipment`, `instructions`, `status`. IDs are 1–128 ASCII letters/digits/underscore/hyphen; schema is numeric integer 1 and status exactly published. Names and normalized-name text are nonblank, trimmed, control-free valid Unicode with at most 120 scalars each. The normalized field is validated text, unused for ordering/search; no search/locale-normalization policy is introduced. Each label array has at most eight distinct, nonblank, trimmed, control-free labels of at most 40 scalars. Instructions are nonblank/trimmed valid Unicode, canonical LF (no CR), at most 2,000 scalars and 8,000 UTF-8 bytes; LF alone is allowed among control characters. Unknown fields, invalid surrogates/types/IDs/order/duplicates and foreign detail IDs fail validation. The native JSON packet is capped at 256 KiB; oversized packets fail closed.

The shared parser validates **all returned documents, including lookahead**, before returning any page. Continuation is transient, based on row 20 only when row 21 exists, and is not an authority token or a snapshot-consistency promise. Append deduplicates by ID; Refresh discards the old traversal and reads anew. Missing, denied, malformed and unavailable states are distinct; a failed page never becomes a successful empty/end result or partial new page. A prior valid page may remain visible during continuation failure, explicitly accompanied by Retry; no failed-page data is appended. Detail missing/archival can be denied by Rules rather than returned as a readable nonexistent document.

Pages/details clear on background, known loss/root retirement and disposal. A suspended visit cannot rebind under its previous authority epoch; foreground needs the root's fresh verification. Native cancellation suppresses delivery, and a 20-second model deadline cancels the read and shows unavailable. A server SDK request may itself stall; no timeout or callback absence is interpreted as cached success. SDK/model lifecycle events are separately attributed from real OS stimuli.

Direct catalog documents are wholly readable to globally eligible accounts, including eligible clients. DTO mapping is not redaction. The create-only fixture script emits only original synthetic, client-safe exercise text/labels/status/schema, rejects an occupied catalog or reused fixture identities/data, and creates trainer fixtures through the existing guarded provisioning primitive. It imports no third-party content/private metadata, and reads credentials from external environment input. No Rule, index, backend product operation or dependency file changed; actual emulator queries worked with existing indexes. Production index readiness remains unproved.
