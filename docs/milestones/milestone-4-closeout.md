## Functional limits at the merged baseline

- The role shells expose Home/Profile, invitations and recovery. There is no live client roster/detail repository, safe trainer client-profile read, profile editing or trainer lifecycle mutation UI. Design-catalog client details are nonfunctional fixtures.
- Mobile Rules allow own account, own exact membership and own minimal client profile reads. Other-user account reads, membership lists and all client-profile lists/writes are denied. Broader matrix/schema entries describe future intent; they are not current grants.
- Invitation summaries are a newest-20 trusted list with no cursor pagination. Internal invitations/receipts/budgets remain Admin-only. No real email delivery, registration/provider choice, production links or manual client creation is supplied.
- Onboarding updates global account basics and per-workspace completion atomically. It does not grant trainers global profile visibility or coaching edit rights. Goals, experience, health, photos and private notes are absent.
- `catalog.ts` contains bounded membership/workspace/account lifecycle primitives; these are not an authorized mobile client-management endpoint. A future handler must authenticate and authorize before invoking them and before replay; Admin bypasses Rules. A lifecycle transition is not automatically equivalent to a designed pause/archive/remove action.
- Permanent command rejection, missing original invitation bearer after restart, incompatible storage and failed settlement can leave same-UID recovery/departure blocked. Reopen the original entry for acceptance retry; no token persistence, forced reset, negative receipt, export or discard policy is introduced.
- No offline grant or workout recovery UI exists. New feature writers must register critical work and honor the existing freeze/epoch/cleanup protocol; a new scope alone never isolates storage.
